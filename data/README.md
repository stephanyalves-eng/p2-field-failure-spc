## NHTSA extraction notes

- Script: `python -m src.data.download_nhtsa` downloads the four zips to `data/raw/nhtsa/` (about 217 MB) and writes `data/processed/nhtsa_complaints.csv` and `data/processed/nhtsa_recalls.csv`. Both outputs are git-ignored and regenerated by the script.
- The flat files are used instead of the NHTSA API because the API returned HTTP 400 for valid make, model and year queries (for example Tesla Model Y 2022 complaints, on every try), which made counts incomplete.
- Models are matched exactly on make and model text after trimming and upper-casing: HYUNDAI IONIQ 5, FORD MUSTANG MACH E, TESLA MODEL 3, CHEVROLET BOLT EV. IONIQ 5 N and BOLT EUV are separate models and are excluded.
- A complaint (`ODINO`) has one row per component it names, so count complaints with unique `ODINO`, not rows.
- Personal and location fields (city, state, VIN, dealer, vehicle operator) are dropped before writing `data/processed`. The complaint narrative `CDESCR` is kept for failure mode coding.

## FAA SDR extraction notes

- Script: `python -m src.data.download_faa_sdr` downloads the 2024 and 2025 files to `data/raw/faa_sdr/` (about 67 MB) and writes `data/processed/faa_sdr_a320_ata24.csv` (git-ignored, regenerated by the script).
- Filter: `AircraftMake` = AIRBUS, `AircraftModel` starting with A318, A319, A320 or A321 (neo models such as A321271NX included), `JASCCode` starting with 24. Result: 154 reports (90 in 2024, 64 in 2025).
- Aircraft registration and serial numbers are dropped.
- JASC titles in `data/mappings/jasc_ata24.csv` are copied from `JASC_Code.doc`. Code 2460 is not printed in that file (the title DC POWER/DISTRIBUTION SYSTEM follows 2450 without a code); it is inferred from the list order and marked to be confirmed.
- Part names are grouped with `data/mappings/sdr_part_groups.csv` (judgment call, open for review).

## Simulated crimp height

- `data/simulated/crimp_height.csv` is the analysis table: one row per measured part (1,800 parts = 2 machines x 3 shifts x 30 days x 2 subgroups of 5), crimp height rounded to the 0.001 mm gauge resolution. It is committed because it is small and is the shared input of the SPC, capability and app steps.
- `data/simulated/crimp_truth.json` holds the hidden truth: the settings, the injected special causes and the true Cp/Cpk they imply. The SPC and capability analysis must not read it to find the causes; it is used only afterwards to score detection and capability estimates.
- Rebuilding with the same seed gives the same files.
